## Phase A′ — two small leftovers (do first, either order, same day)

### SQL-A5 — keep the resource oracles from hanging the test host  *(S)*
- **Why:** the new oracles (depth-20 `not`, 100,000-item `select`, 400 KB of `[`) run in-process. A regression to the
  exponential or recursive path would hang or kill the test host instead of failing a test.
- **Do:** `ProcessIsolated.Run(...)` helper (child process, `DOTNET_GCHeapHardLimit`, hard timeout, assert exit code and
  last output line), used for exactly three cases: CQM depth 14–20 `not`, CQM 100,000-item `select`, overlay 400 KB `[`.
  Keep the cheap in-process assertions as they are.
- **Accept:** temporarily reverting the guard (locally) makes the harness fail within its timeout rather than hang.

### SQL-A6 — bound the error lists and bind `Query:*`  *(S → M when the host exists)*  — QA TS5-01, TS5-02
- **Do (6a, now):** cap the errors returned by `CqmJson.Deserialize` and by the overlay importer at a fixed number
  (suggest 100) and expose `Truncated`/`TotalErrors` on both result types.
  **Accept:** a 156 KB overlay with 80,000 bad scalars returns ≤ 100 errors plus the total; a CQM with 11,000 bad nodes
  likewise; the first error and its path are unchanged for small documents.
- **Do (6b, with SQL-07, not before):** bind the `Query` section into `CqmLimits` in one place.
  **Accept:** changing `Query:MaxJoins` in configuration changes the verdict on a document with that many joins.
