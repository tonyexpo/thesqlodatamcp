## Findings

### TS3-01 — medium — a null relationship join pair still crashes the importer

- **Where:** `src/TheSqlODataMcp.Core/Catalog/SemanticOverlayImporter.cs:340-362`, called after schema evaluation
  at `:158-186`; regression coverage in `SemanticOverlayImporterQaTests.cs` handles entities/fields, not this list.
- Against a valid catalog containing `sales.Secrets(Id int)`, submit:

```yaml
catalogVersion: '1.0'
entities:
- source: sales.Secrets
  relationships:
    self:
      target: sales.Secrets
      join: [null]
```

- **Observed:** `NullReferenceException: Object reference not set to an instance of an object.` `pair` is null and
  `pair.SourceField` is dereferenced. Schema invalidity is detected first, but reference traversal still continues
  without guarding this remaining DTO node. This is a tiny ordinary invalid document, not an exhaustion probe.
- **Impact:** the collected-errors contract is still broken for malformed input. No remote crash is claimed because
  no import endpoint exists yet. The original `entities:[null]` and numeric examples are genuinely fixed.
- **Action:** guard every collection element/reference traversal or make traversal conditional on structural validity
  without losing independently actionable diagnostics. Add null join-pair cases in both import entry points.
- **Status:** independently reproduced; residual TS-04, open.

### TS3-02 — medium, before hosting — the public read-view object graph retains hidden-target physical FKs

- **Where:** `src/TheSqlODataMcp.Core/Catalog/CatalogReadView.cs:23-33`, specifically the unchanged
  `entity.Physical`; `TechnicalEntity.Relationships`; tests `CatalogReadViewTests.cs:36-63`.
- **Own probe:** construct real technical `Orders(Id)` with `CatalogRelationship("FK_Orders_Secret", sales.Secrets,
  Id→Id)`, merge an overlay with `Secrets.exposed=false`, then construct `CatalogReadView`.

```text
view.FindEntity(Orders).Relationships.Count                       = 0
view.FindEntity(Orders).Physical.Relationships[0].Target            = sales.Secrets
JsonSerializer.Serialize(view.Catalog).Contains("Secrets")         = true
```

- Hidden entity search/lookup and the **merged** relationship list are properly filtered; the underlying physical
  FK graph is not. The shipped read-view fixture puts relationships only in the merged list and leaves physical
  entities without FKs, so it cannot detect this seam.
- **Impact:** this is a demonstrably unsanitized library projection, **not an existing public data leak**. Adapters
  serializing the advertised public view or describing its physical relationships could reveal hidden metadata.
  `MergedCatalogCanonicalJson.Serialize` uses a narrower explicit projection and is not asserted to leak that FK;
  the default object serializer and direct physical access do. Requiring adapter wiring alone does not sanitize it.
- **Action:** expose a purpose-built safe DTO/view without an unfiltered physical graph, or sanitize the physical
  relationship projection too. Test a discovered FK in the physical catalog and the actual planned serializers;
  retain the unrestricted internal catalog for administration.
- **Status:** independently reproduced; open before any public metadata/query adapter.

### TS3-03 — low — exact temporal grammar accepts a decimal separator with zero digits

- **Where:** `src/TheSqlODataMcp.Core/Cqm/CqmExpression.cs:106-142`; `docs/cqm.md:65-77`.
- Own calls to the public `CqmJson.Deserialize` with otherwise valid queries accept:

```text
time            "12:30:00."                  success=True
datetime        "2026-11-02T12:30:00."       success=True
datetimeOffset  "2026-11-02T12:30:00.Z"      success=True
```

- `FFFFFFF` is optional in .NET custom formats, including the zero-digit case. The contract documents either no
  fractional component or **1–7 digits**, not a dangling dot. Original `"November 2"`, `"12:30"`, missing offsets and
  nine fractional digits are now rejected correctly; seven digits plus `Z` is accepted.
- **Impact:** small strict-wire-contract discrepancy, not the old host-clock/timezone ambiguity and not observed SQL
  misexecution. **Action:** require at least one digit after a present separator and test both constructors/parser.
- **Status:** reproduced; open, lower priority than TS3-01/02.
